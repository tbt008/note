# 记忆系统

记录日期：2026-10-10
标签：Claude Code/记忆/上下文

## 背景

模型本身没有可靠的跨请求记忆。Claude Code 通过多层记忆机制保存协作规则、长期事实、Agent 角色经验和当前会话状态，避免每次都从零开始理解用户和项目。

## 要点

### 四层记忆

| 层次 | 定位 | 内容 |
|-|-|-|
| 指令记忆 | 行为说明书 | `CLAUDE.md` 系列规则 |
| 长期记忆 | 不可推导的知识 | 用户偏好、反馈、项目事实、外部引用 |
| Agent 记忆 | 角色私有经验 | 特定 Agent 的方法和约束 |
| 会话记忆 | 当前任务摘要 | 目标、状态、文件、错误、工作流 |

### 指令记忆作用域

- Managed：平台或组织托管规则。
- User：`~/.claude/CLAUDE.md`。
- Project：项目根目录和 `.claude/rules/` 下的共享规则。
- Local：`CLAUDE.local.md`，仅当前机器私有。

### 长期记忆四类型

- **user**：用户身份、偏好、知识背景。
- **feedback**：用户对行为的纠正和正面确认。
- **project**：项目进展、决策、截止日期。
- **reference**：外部系统中信息的位置。

封闭分类避免标签膨胀。`feedback` 同时记录失败和成功经验，防止用户验证过的方法被后续会话“改进”掉；`project` 必须把相对日期转成绝对日期；正文需要写清事实、原因和适用方式。

### 不应保存的内容

- 可直接从当前代码推导的架构、路径和约定。
- Git 历史和最近改动。
- 已修复在代码里的调试过程。
- 已存在于 `CLAUDE.md` 的规则。
- 临时任务状态和当前对话细节。

### 召回过程

1. 扫描项目对应记忆目录。
2. 生成清单并交给模型评估相关性。
3. 过滤过时、重复、噪声和不可信记忆。
4. 将少量相关记忆注入用户上下文。

`MEMORY.md` 是索引，不是长期知识容器。

## 示例

用户说“这次代码风格很好，以后就这样写”。系统应保存为 `feedback`，包含规则本身、用户为什么偏好它、什么时候应用。下次会话不需要用户重复说明，Agent 也能延续该风格。

## 结论

记忆系统的核心不是“多存”，而是区分哪些信息不可从当前环境中推导。规则放 `CLAUDE.md`，长期事实放 memory，当前任务放 session memory，角色经验放 agent memory。
