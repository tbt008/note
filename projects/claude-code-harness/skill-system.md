# 技能系统

记录日期：2026-10-10
标签：Claude Code/技能/工作流

## 背景

如果每次代码审查、提交或诊断都重复输入一套提示词，既浪费上下文，也难以保持流程稳定。技能用于固化经过验证的 AI 工作流，本质是提示词模板、元数据和执行上下文的组合。

## 要点

### 技能格式

```text
.claude/skills/
  review/
    SKILL.md       # frontmatter + 提示词
    templates/
      report.md
```

目录结构允许技能携带模板、配置和参考文档，并通过技能目录变量引用资源，使其成为自包含单元。

### 双重调用

- **用户手动**：输入 `/commit` 等命令。
- **模型自动**：根据任务意图判断需要某个技能，再调用 SkillTool。

两条路径最终进入相同的执行逻辑，用户不需要记住所有命令名。

### 六个来源与优先级

技能从内置、用户、项目、插件、MCP 等多个来源加载，并按固定顺序合并。前置来源优先，内置核心技能不能被项目技能同名覆盖，保证核心行为可预测。

### 懒加载

启动时只加载 name、description、whenToUse 等 frontmatter；完整正文在用户或模型真正调用时才进入上下文。这样技能列表展示成本低，执行成本按需支付。

### System-reminder 发现

技能列表通过 `<system-reminder>` 动态注入，告诉模型当前有哪些技能、适用场景和调用方式。执行时模型调用真实的 `Skill` 工具，加载正文后按技能继续推理。

### Inline 与 Fork

- **Inline**：在当前上下文中展开技能正文，适合短流程和需要当前状态的任务。
- **Fork**：创建子 Agent 执行，隔离上下文并复用父级缓存，适合长流程或高污染任务。

### 安全模型

技能具有信任层级，MCP 技能做安全隔离，Fork 模式限制对主会话的影响。frontmatter 只允许安全属性进入模型可见描述，避免通过不可信元数据注入权限语义。

## 示例

用户说“帮我提交代码”。模型看到 commit 技能的 whenToUse 与当前任务匹配，调用 `Skill(skill: "commit")`，系统加载该技能正文，模型按其中的步骤检查 diff、写提交信息并执行提交。

## 结论

技能系统把重复工作流从聊天历史中抽离成可版本化资产。关键设计是“轻量发现、按需加载、双路径触发、安全隔离”。
