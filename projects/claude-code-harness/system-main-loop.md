# 系统主循环

记录日期：2026-10-10
标签：Claude Code/主循环/异步

## 背景

系统主循环回答一个问题：用户发出一条消息后，Claude Code 如何连续调用模型和工具，直到任务完成。它分为两层：`QueryEngine` 管理会话生命周期，`query()` 管理单次查询内的循环。

## 要点

### 双层生成器

- **QueryEngine**：负责配置、消息持久化、预算追踪、结果组装和 SDK 输出。
- **query()**：负责“API 调用 → 工具执行 → 继续或退出”的核心状态机。
- 两层都是异步生成器，调用方用 `for await` 实时消费事件。

选择 Generator 而不是回调或 Promise，是因为它同时提供流式输出、背压控制和级联取消。用户中断时，`generator.return()` 能沿调用链传播清理逻辑。

### 一次循环迭代

```text
读取消息历史
  -> 必要时压缩上下文
  -> 调用模型
  -> 流式识别 assistant 输出
  -> 发现 tool_use
  -> 并发或串行执行工具
  -> 收集 tool_result
  -> 继续下一轮模型调用
```

### 流式工具执行

模型还在生成时，已经完整解析出的工具调用可以提前进入 `StreamingToolExecutor`。只读且并发安全的工具可以并行执行，用模型继续输出的时间掩盖工具延迟；有写入副作用或可能竞态的工具保持串行。

### 错误恢复与扣留

系统有多个继续点，分别处理 Prompt Too Long、Max Output Tokens、压缩、续写等恢复路径。可恢复错误会先扣留在内部消息中，不立即暴露给 UI 或 SDK；恢复成功后用户无感知，全部策略失败才向上抛出。

### 停止条件

- 模型返回纯文本，没有工具调用。
- 达到最大轮次。
- USD 预算超限。
- 用户中断。
- 不可恢复错误。
- 连续 3 次自动压缩失败并触发熔断。

## 示例

模型输出被 `max_output_tokens` 截断时，系统可以提升输出上限或注入续写指令。恢复成功后，截断错误不进入外部事件流；如果三次续写都失败，才把错误交给上层处理。

## 结论

主循环是 Claude Code 的骨架：模型负责决策，代码负责稳定执行、并发控制、预算约束和错误恢复。异步生成器让这些复杂逻辑仍能保持线性控制流。
