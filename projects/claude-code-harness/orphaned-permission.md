# 孤儿权限

记录日期：2026-10-10
标签：Claude Code/权限/状态恢复

## 背景

`orphanedPermission` 指的是一个 `tool_use` 已经发起权限请求，但权限结果回来时，原来等待它的执行现场已经不存在。这个晚到的结果不能直接丢弃，否则会破坏消息链，也无法表达用户刚刚做出的允许或拒绝决定。

## 要点

### 正常权限流程

```text
assistant 发出 tool_use
  -> 系统请求权限
  -> 用户允许或拒绝
  -> 当前循环消费结果
  -> 执行工具或生成拒绝结果
```

### 变成孤儿权限的原因

- 原循环已经结束。
- 进程切换或会话恢复。
- 控制响应晚到。
- 当前执行上下文已经不在原位置。

### 恢复处理

下一次 `submitMessage()` 开始时，系统先处理遗留的孤儿权限：

1. 从 assistant 消息中找到原 `tool_use` block。
2. 读取用户最终是 allow 还是 deny。
3. 如果允许，应用可能存在的 `updatedInput`。
4. 确保 assistant `tool_use` 已进入消息历史，避免只有 `tool_result` 没有 `tool_use`。
5. 重新执行工具或生成拒绝结果。
6. 把输出补写回 transcript 和 SDK 流。

## 示例

模型请求执行 Bash，用户几秒后才点击允许，但原循环已经不再等待该结果。这个“允许”会变成孤儿权限。下一次用户提交消息前，系统先补执行这个 Bash 工具，再处理新输入。

## 结论

孤儿权限是主循环异步性和人工审批之间的竞态恢复机制。它把迟到的权限结果安全补回消息链和执行链，保证会话历史不断裂。
